# Contributing to tap-on-shoulder

Thanks for your interest! The project is at the **design stage**, which is when feedback has the most impact.

## Ways to help right now

- **Share a story.** Tell us about a time Claude was waiting and you missed it, or got pinged for nothing. Real cases shape the classifier and the defaults.
- **Test an assumption.** Pick an item from [Unverified](docs/design/verified-interfaces.md#unverified), try it with your Claude Code version, and report what happened.
- **Critique the design.** Read [How it works](docs/how-it-works.md) and [Security](docs/security.md), then open an issue with the `design` label.
- **Improve the docs.** Typos, unclear sentences, and missing links all make great first PRs.

## Ground rules

- **Mark every claim.** Use **Verified** with a link to the official docs, **Proposed**, or **Unverified**. Never present an assumption as fact.
- **Observe, never act.** Proposals that answer, approve, resume, or wake Claude sessions are out of scope.
- **Privacy first.** Don't paste real transcripts, secrets, or private code into issues. Redact them, or describe the case instead.
- **Keep it small.** Each feature has to justify the complexity it adds.

## Pull requests

1. Open an issue first for anything bigger than a doc fix.
2. Keep each PR focused on one change.
3. Update the docs in the same PR as the change they describe.

## Security issues

Please don't open public issues for vulnerabilities. See [SECURITY.md](SECURITY.md).
